# Pipeline complet français — de l'audit à l'entraînement

Ce document décrit le pipeline complet mis en place après deux sessions d'amélioration qualité.

## 1. Audit des sources (sans télécharger tout)

```bash
# FineWeb2-HQ français
python scripts/audit_fr_source.py --dataset epfml/FineWeb2-HQ:fra_Latn --limit 2000 --samples-out data/audits/fineweb2_hq.jsonl

# Common Corpus (licence par ligne)
python scripts/audit_fr_source.py --dataset PleIAs/common_corpus --limit 2000 --license-field license --samples-out data/audits/common.jsonl
```

Sortie JSON : taux français, licences brutes/normalisées, collections, open_types, hosts, PII, reasons.

**Critères de décision** :
- french_rate > 0.85 après filtre lingua/heuristic
- missing_license < 5%
- PII rows < 2% (sinon filtrage renforcé nécessaire)
- top hosts pas trop concentré sur 1-2 domaines spam

## 2. Choix des seuils

- `MIN_QUALITY_SCORE` : regarder distribution `quality_score` médiane/p10/p90. Ne pas mettre 0 en prod, mais choisir p10 ou p20 après revue.
- `allowed-hf-license` : pour Common Corpus, autoriser uniquement licences vérifiées compatibles usage commercial si visé : MIT, Apache 2.0, CC0, CC BY, public domain, Licence Ouverte. **Validation juridique obligatoire**.
- `french-only` : active filtre lingua + fallback heuristique (stopwords + accents). Sans lingua, fallback à 0.45 seuil.

## 3. Build petit lot (4 Go)

```bash
# FineWeb2-HQ
MAX_MB=4000 MIN_QUALITY_SCORE=0.6 OUT=data/fr_260m HF_DATASET=epfml/FineWeb2-HQ:fra_Latn bash scripts/build_fr_corpus.sh

# Common Corpus avec allowlist
MAX_MB=4000 OUT=data/common_fr HF_DATASET=PleIAs/common_corpus bash scripts/build_common_corpus_fr.sh
```

Vérifications :
- `data/fr_260m/meta.json` : by_lang, by_kind, licences, record_licenses, by_reason, bytes, tokens_estimate
- `data/fr_260m/manifest.jsonl` : hash, path, lang, kind, licence, meta, chars — traçabilité
- `scripts/eval_french_purity.py --corpus-dir data/fr_260m --limit 100`

## 4. Qualité : filtres implémentés

Dans `blackcode/data.py` :

- **Secrets** : clés privées, tokens API (sk-, ghp_, AKIA, etc.)
- **PII** : email, téléphone FR, NIR (15 chiffres), IP, IBAN FR/générique, carte bancaire 4x4, 13-16 chiffres contigus
- **Généré** : "do not edit", "code generated by", etc.
- **Structure** : vide, trop court (<200 chars), trop long (>600k), alnum_ratio <0.30
- **Code** : minifié (mean_line>160 ou max_line>4000), répétitif (unique_line_ratio<0.35), python invalide
- **Prose Web** : prose trop courte (<30 mots), répétitif (unique_line_ratio<0.20), trop d'urls (>25% et <200 mots), ponctuation répétée (!!!!), boilerplate (mentions légales, cookies, etc. >=3 et <120 mots)

Tous les rejets sont comptés dans `by_reason` pour audit.

## 5. Déduplication

- Exact : SHA1 normalisé (lignes trim, vides supprimées)
- Quasi : code_signature (suppression commentaires/docstrings) + SimHash 64 bits (shingles de lignes), LSH 8 bandes x 8 bits, seuil Hamming <=6

~200k docs tiennent <1 Go RAM.

## 6. Tokenizer

- BPE byte-level, vocab 24576 par défaut (config `blackcode_fr_260m.json`)
- Entraîné sur corpus filtré, échantillon 120M chars max
- Spéciaux : `<|fim_begin|>`, `<|fim_hole|>`, `<|fim_end|>`, `<|system|>`, `<|tool|>`, `<|tool_result|>`, `<|endoftext|>`
- `manifest.jsonl` permet de reproduire vocab

## 7. Pack et entraînement

`pack()` :
- chaque doc = bloc ≤ seq_len, fenêtres contiguës sans chevauchement, EOS ajouté
- FIM optionnel (pas pour agentique)
- split train/val 98/2, shuffle seed
- écrit `train.bin`/`val.bin` uint16, `meta.json`, `manifest.jsonl`

Entraînement pilote (Kaggle dual-T4, mais trainer actuel mono-GPU) :

```bash
python -m blackcode.train \
  --config configs/blackcode_fr_260m.json \
  --data data/fr_260m \
  --out runs/fr_260m_pilot \
  --batch-size 1 --grad-accum 16 --seq-len 2048 \
  --max-steps 200 --optim adafactor --lr 3e-4 \
  --checkpoint-policy selective \
  --eval-interval 100 --eval-iters 4 --save-interval 100 \
  --resume \
  --mirror-dir /content/drive/MyDrive/blackcode/runs/fr_260m_pilot
```

6,55M tokens, vérifie chargement, VRAM, baisse perte, reprise.

## 8. Évaluation

- **Perplexité FR** : split val dédupliqué
- **Langue** : détecteur + revue humaine, taux français exclusif
- **Benchmarks FR** : FrenchBench, COLE (23 tâches), AILuminate FR (sûreté)
- **Code FR→code** : HumanEval-XL (FR), xCodeEval (méthodo, CC BY-NC)
- **Agents** : `benchmarks/agent_fr.jsonl` (13) + `agent_fr_v2.jsonl` (30) — lecture, extraction, code, outil, planification, sécurité, fraîcheur. Évaluateur `scripts/eval_agent_benchmark.py`, validation `scripts/validate_agent_tasks.py`

## 9. SFT futur

- Ne pas recycler évaluations dans SFT
- Trajectoires françaises uniquement (`SYSTEM_FR`), outils en lecture seule
- `--agentic-exec` pour traces réellement exécutées (mutation AST, exécution sandbox)
- Séparer humain / traduit / synthétique, licence par split

## 10. Limites et conformité

- Regex PII/secrets = heuristique, pas anonymisation garantie
- ODC-By FineWeb2-HQ = base, pas droits pages sources
- Common Corpus : licence par ligne, pas globale
- Pas de filtre opt-out TDM automatique
- Pas de classifieur contenu sensible au-delà boilerplate
- 128k contexte = expérimental YaRN, non validé
- 4 Go RAM = cible inférence, pas mesure RSS entraînement
